# 成理工程生存指南 & 飞跃手册 - 内容设计框架文档

## 项目概述

本项目旨在为成都理工大学工程技术学院（以下简称"工程学院"）的在校生和毕业生提供两个核心知识库：

- **生存指南**：校园生活实用信息，以及帮助学生理解大学处境和专业选择的文章
- **飞跃手册**：毕业出路思考与来源可确认的升学、就业和留学经验

参考项目：

- [南方科技大学飞跃手册](https://sustech-application.com/) — VitePress 框架
- [上海交通大学生存手册](https://github.com/SurviveSJTU/SurviveSJTUManual) — GitBook 框架
- [上海交通大学飞跃手册](https://survivesjtu.github.io/SJTU-Application/) — Docsify 框架

## 内容管理策略

### 帖子组织方式

采用**按主题分类 + 案例标签索引**的方式：

- 一级目录：生存指南 / 飞跃手册
- 二级目录：具体主题（考研、留学、就业等）
- 飞跃手册案例筛选字段：年份，以及各方向对应的目标层次、地区、专业、行业或岗位类型（通过 VitePress frontmatter 实现）

生存指南中的实用条目和观点文章不要求使用案例元数据。飞跃手册的出路思考文章是编辑部分析；经验案例必须来自本人投稿或获得明确授权的访谈，二者不能混写。

留学目的地按亚洲、欧洲和大洋洲建立地理目录。国家作为可展开目录，国家首页按“教育与项目特点、院校筛选、申请门槛、申请方法与窗口、通用材料”组织；首批保留院校各自建立独立页面，说明定位、值得调查的方向、首要排除项和官方入口。

院校筛选以当前最新 QS 世界大学综合排名作为检索信号，不把排名写成录取概率或项目质量。当前页面使用 QS 2027：原则上优先保留全球前 500，排名更后或未进入综合榜的院校只有在特定学科、应用型培养或研究生院结构上存在明确理由时，才以“学科例外”保留。海外分校必须注明排名属于母校，不得把母校名次写成分校独立排名。排名更高但因竞争、专业匹配或成本不适合作为首批主申的院校，应在国家首页列出并说明原因。

院校列表不构成保底或录取难度排名，没有可靠正文的目的地不保留空白页面。QS 版本更新时，应同步核查国家首页和院校页，并保留核验日期。

语言考试使用独立目录，每种主流考试单设页面，记录用途、官方报名入口、当前考试信息和项目接受范围的核查方法。费用、考位与考试结构不写成长期不变的常量。

### 增删子模块操作指南

核心原则：**目录结构即站点结构，添加内容无需修改代码配置**。

| 操作             | 步骤                                                                                                              |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| **新增子模块**   | 1. 创建新文件夹（如 `docs/survival/library/`）<br>2. 添加 `_category.md` 定义标题和描述<br>3. 添加内容 `.md` 文件 |
| **删除子模块**   | 直接删除对应文件夹，构建时自动消失                                                                                |
| **重命名子模块** | 修改 `_category.md` 中的 `title` 字段                                                                             |
| **调整排序**     | 修改 `_category.md` 中的 `order` 字段或各文件 frontmatter 中的 `order`                                            |
| **移动内容**     | 在文件系统中移动 `.md` 文件，更新 frontmatter 即可                                                                |

### 目录约定与文件命名

```text
docs/survival/academics/
  ├── _category.md        # 分类元信息（标题、描述、图标、排序）
  ├── exam-tips.md        # 具体内容文件
  └── gpa-guide.md
```

| 约定                | 说明                                                     |
| ------------------- | -------------------------------------------------------- |
| `_category.md`      | 每个子目录的元信息文件，定义该分类的标题、描述、排序权重 |
| 文件名              | 使用英文短横线命名（`kebab-case`），简短且有意义         |
| Frontmatter `order` | 控制同一目录内文件的排序（数字越小越靠前）               |
| Frontmatter `title` | 页面标题，同时用于侧边栏显示                             |

### Frontmatter 规范

#### 生存指南文章

```yaml
---
title: 报到须知
order: 1
description: 新生报到流程及注意事项
---
```

#### 飞跃手册文章

飞跃手册的投稿方向由目录决定，frontmatter 只保存作者信息和该栏目的筛选字段。不要用一个通用 `type` 字段同时表示“考研 / 留学 / 就业”；就业栏目中的 `type` 专门表示岗位类型。

| 目录           | 筛选字段                                             | 字段含义                                               |
| -------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| `postgraduate` | `year`、`target`、`major`、`zone`、`degree`、`cross` | 结果年份、目标层次、报考方向、选区、培养类型、是否跨考 |
| `abroad`       | `year`、`region`、`major`                            | 结果年份、申请地区、申请方向                           |
| `employment`   | `year`、`industry`、`type`                           | 结果年份、行业、岗位类型                               |

考研案例示例：

```yaml
---
title: 跨考计算机的一年：择校调整与复试结果
author: 匿名
year: 2025
target: 双一流
major: 计算机
zone: A区
degree: 专硕
cross: 跨考
description: 一份包含择校调整和失败复盘的跨考样本
date: 2025-06-15
---
```

`author` 是页面公开署名，可以填写“匿名”；维护者仍需在私下确认作者或受访者身份。`description` 应说明文章解决的问题或样本背景，不使用“经验分享”“干货总结”等无信息描述。

`region` 使用具体目的地，例如“中国香港”“英国”“日本”，大洲分组由筛选组件生成，不填写“欧洲”等上级区域。仅用于界面开发的页面可以设置 `placeholder: true`，但必须在页面和案例卡片上明确显示“示例占位”，不得包含虚构录取结果。

## 投稿流程

### 面向投稿者

1. **Git 熟悉者**：Fork → 新建分支 → 选择与文章类型对应的模板 → 编写 Markdown → 发起 Pull Request
2. **不熟悉 Git 者**：通过邮件提交 Word 或 Markdown 文件并注明投稿分区，由维护者整理元数据和上架

### 面向维护者

1. 确认文章类型和目标栏目，不用同一结构重写所有投稿
2. 核对经历来源、授权范围和易变化事实，再整理正文
3. 放入对应目录，填写与筛选器一致的 frontmatter
4. 运行格式、规范和构建检查
5. 审核内容后合并到主分支并自动部署

飞跃手册案例审核还需要确认：

- 作者身份可以匿名，但经历来源必须可由维护者确认。
- 文章应区分亲历、转述和个人判断，并写明关键经历发生的年份。
- 涉及政策、费用、申请要求和就业规则时，应提供来源与查询日期。
- 文章需要包含实际结果、失败或调整，不能只保留成功方法。
- 不把单一个案写成普遍规律，也不根据模板或网络材料生成虚构案例。

## 投稿模板

模板文件保存在 `docs/templates/`，不参与 VitePress 构建：

| 文件                            | 用途                 |
| ------------------------------- | -------------------- |
| `survival-entry.md`             | 校园实用信息         |
| `survival-perspective-entry.md` | 校园处境与观点文章   |
| `leap-postgraduate-entry.md`    | 考研经历             |
| `leap-abroad-entry.md`          | 留学申请经历         |
| `leap-employment-entry.md`      | 就业或实习经历       |
| `leap-entry.md`                 | 飞跃手册共通审核要求 |

模板是问题清单，不是需要逐项填满的问卷。编辑时应删除不适用的小节，并根据真实材料重命名标题。

生存指南实用条目优先说明适用条件、步骤、失败点、替代办法和信息时效；观点文章围绕一个中心问题组织事实、机制、选择影响和边界，不强制添加 Tips。

飞跃手册经验文章共同要求：

1. 只写与选择和结果相关的背景和约束。
2. 说明为什么选择这条路，以及比较过的替代方案。
3. 记录实际投入、失败、拒绝和关键调整。
4. 给出最终结果，避免只展示最好成绩或最好 offer。
5. 说明经验的适用边界，并为易变化事实提供来源和日期。

## 视觉设计风格：工程构成主义 + 阅读手册

### 风格定位

首页使用强构成主义主视觉建立品牌识别，正文页则退回安静、耐读的手册界面。两者共享颜色、字体和结构线，但不共享相同的装饰密度。

### 设计原则

| 原则       | 说明                                                 |
| ---------- | ---------------------------------------------------- |
| 内容优先   | 正文保持约 800px 阅读宽度和不低于 16px 的基础字号    |
| 视觉分级   | 首页使用天体弧面与斜向构图，正文只保留结构线和短色标 |
| 核工业识别 | 以 HL-1 工程线稿作为唯一主要具象图形                 |
| 限定色板   | 暖灰米白、矿物红、近黑和低饱和赭黄                   |
| 主题适配   | 亮色和暗色分别设计，不能依赖简单反色                 |

### 色彩方案

```css
/* 亮色模式 */
--site-paper: #ebe8de;
--site-paper-deep: #d8d5ca;
--site-ink: #151718;
--site-red: #b9362a;
--site-ochre: #c99a32;

/* 暗色模式 */
--site-paper: #0d0f10;
--site-paper-deep: #171a1b;
--site-ink: #f2eee0;
--site-red: #d64732;
--site-ochre: #d0a94b;
```

### 构成主义装饰元素

- **首页 Hero**：HL-1 线稿、矿物红天体弧面、深色斜向结构块
- **信号射线**：以装置中心为原点的不等长赭黄分段线，中线必须与装置中心持平
- **正文标题**：黑色水平结构线叠加短矿物红标记
- **侧边栏与表格**：使用纸面深浅变化和 1px 分隔线，不添加大型几何装饰
- **暗色首页**：长斜块保持深色，避免遮挡浅色线稿和设备标注

### 字体方案

```css
/* 标题与正文 */
--font-sans: 'Noto Sans CJK SC', 'PingFang SC', 'Microsoft YaHei', sans-serif;

/* 代码/标签 - 等宽 */
--font-mono: 'JetBrains Mono', 'Fira Code', monospace;
```

更完整的颜色、排版、响应式和使用边界见[视觉设计规范](./design-system)。
